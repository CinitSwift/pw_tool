# 架构说明

本文档描述当前仓库已经实现并验证过的桌面端架构边界，只记录现状，不描述未来计划。

## 总览

应用采用 Electron 三层结构，并把可复用的领域模型下沉到 shared 层：

- `src/main/`：主进程，负责应用生命周期、数据库、窗口、托盘、IPC 注册和 `SessionService`。
- `src/preload/`：预加载层，向渲染层暴露受限的 `pwTool` API。
- `src/renderer/`：React 渲染层，负责主窗口、迷你窗、历史、设置与启动错误页。
- `src/shared/`：跨进程共享的领域类型、计费/时间/快照/CSV 等纯逻辑。

核心原则是：**会话状态与持久化写入由主进程统一掌控，渲染层不直接写数据库。**

## 分层边界

### Main

主进程承担以下职责：

- 启动应用并创建窗口。
- 初始化本地数据库。
- 在数据库可用时创建单一 `SessionService` 实例，作为当前会话和历史读写的事实来源。
- 注册 IPC handler，并把快照变化广播到窗口目标。
- 管理主窗口、迷你窗和托盘相关生命周期。

当前实现中，主进程会给渲染层 URL 附带窗口模式参数 `?window=main|mini`，用于区分主窗与迷你窗渲染路径。

如果数据库初始化失败，主进程不会让渲染层直接进入正常计时界面，而是让前端进入启动错误页流程，明确提示本地数据库初始化失败。

### Preload

预加载层只暴露最小化的桥接 API，不把 Electron 原始对象直接暴露给 React。当前公开入口聚焦以下四组能力：

- `session`
- `history`
- `settings`
- `window`

渲染层通过这些固定能力调用主进程，不直接访问 `ipcRenderer`。

### Renderer

渲染层负责界面状态与交互，不负责数据库持久化。

- 主窗口模式下展示计时、历史和设置入口。
- 迷你窗模式下直接渲染 `MiniTimer`，复用同一套会话快照数据。
- 启动错误页用于承接数据库初始化失败场景。
- 历史页与设置页使用专门的 API 入口，不通过隐藏的主窗口副作用来更新数据。

当前迷你窗只消费当前 `SessionSnapshot` 与窗口相关 API，不单独复制一套状态机逻辑。

### Shared

`src/shared/` 保存跨进程共享的纯逻辑与类型定义，包括：

- 领域类型
- 运行时快照/会话状态辅助逻辑
- 时间与计费纯函数
- CSV 序列化逻辑

其中 CSV 导出使用共享域内的统一 serializer，确保主进程导出的内容与业务格式规则保持一致。

## IPC 与数据流

当前数据流是单向且受控的：

1. 渲染层通过 preload 暴露的 `pwTool` API 发起请求。
2. preload 把请求转成固定 IPC 通道调用主进程。
3. 主进程中的 `SessionService`、历史仓储或设置逻辑执行操作。
4. 需要更新时，主进程把最新快照广播给已注册的窗口目标。
5. 主窗口和迷你窗消费同一份快照来源，而不是各自维护独立会话真相。

这保证了“主窗口、迷你窗、历史记录和设置”之间不会出现多套并发事实源。

## SessionService：单一事实源

当前实现里，`SessionService` 是会话相关状态转换与持久化的单一事实源：

- 当前会话快照由它统一生成。
- 会话开始、暂停、继续、结束等动作由它协调。
- 快照更新由它统一广播到窗口目标。
- 历史相关查询与编辑需要通过主进程注册的路径进入，而不是由渲染层自行拼装数据库写入。

迷你窗与主窗口共享同一个 `SessionService` 所派生出的快照，因此两个窗口展示的是同一份运行中状态。

## 历史、导出、设置与迷你窗边界

### 历史记录

历史视图负责读取本地历史数据、筛选、删除、展示完成态信息，并支持编辑时间片段。

当前历史编辑走独立路径：

```ts
history.editSegments({ sessionId, segments })
```

这条路径不依赖 active session 上下文，目的是把历史编辑与当前运行中的会话编辑边界分开。

### CSV 导出

CSV 导出在本地完成，使用 shared 层的统一序列化逻辑。当前约束包括：

- 使用统一表头与字段格式。
- 本地导出，不依赖网络服务。
- 领域层负责 CSV 规则，界面层只负责触发导出与承接结果。

### 设置

设置通过专门的 `settings` API 读写，聚焦本地默认参数和迷你窗相关配置。设置页本身不直接操作数据库层实现细节，而是经由 preload → IPC → 主进程链路完成保存。

### 迷你窗

迷你窗是主窗口之外的紧凑视图：

- 通过 `?window=mini` 进入迷你窗模式。
- 复用当前会话快照。
- 支持与主窗口协同，而不是成为第二套独立业务容器。

## 本地数据约束

- 当前应用是完全离线工具。
- 不存在登录态、云同步或遥测上报链路。
- 数据保存在本地 Electron 用户数据目录中。
- `ELECTRON_USER_DATA_DIR` 目前只应被视为测试/E2E 的目录覆盖方式，不作为正式产品文档中的用户能力承诺。

## 启动失败与保护性界面

如果数据库初始化失败，当前实现会进入启动错误页，而不是展示一个看似可用但实际不可写入的计时界面。这个保护性分支是主进程启动编排与渲染层错误页协同完成的。

## 不在本文档范围内的内容

以下内容没有作为当前已实现事实写入本文档：

- 云同步
- 账号登录
- 自动更新
- Linux 打包链路
- 签名与公证流程
- 远程 API 或遥测平台

如果未来实现了这些能力，应在代码落地并验证后再更新文档。
