# 陪玩小工具桌面端设计规格

日期：2026-08-06

状态：已确认设计，等待规格审阅

## 1. 产品目标

“陪玩小工具”是一款完全离线的 macOS 与 Windows 桌面应用，用于记录单局陪玩服务的有效时长，并实时计算当前应得金额与抽成金额。

用户点击“开始计时”后立即开始一局；计时期间可以暂停、继续、修改时间、调整本局计费参数和填写备注；游戏结束后手动点击“结束本局”。完成的记录保存在本机历史中，可以调整时间、重新计算金额、删除或导出 CSV。

首版成功标准：

- 开始、暂停、继续和结束操作快速明确。
- 窗口隐藏、系统休眠、应用卡顿或重新启动不会依赖定时器累加而丢失时长。
- 每一笔金额都能追溯到时间片段、分钟取整和计费档位。
- 异常退出后的未完成记录不会被静默结算或删除。
- 主窗口适合长期放在游戏、语音和订单窗口旁边使用。
- macOS 和 Windows 均可生成可安装的本地安装包。

## 2. 首版范围

首版包含：

- 单任务计时。
- 暂停与继续，暂停期间不计时、不计费。
- 当前局应得金额和抽成金额的实时展示。
- 三种计费方式。
- 计时中调整所有已存在的时间节点。
- 完成后调整全部时间片段并立即重算。
- 自由文本备注。
- 本地历史记录、查看、删除、搜索和状态筛选。
- CSV 导出。
- 主窗口、手动置顶的迷你计时窗和系统托盘。
- 异常退出后的恢复、重新计时或不恢复流程。
- GitHub Actions 分平台构建 macOS 与 Windows 安装包。

首版不包含：

- 登录、服务器、云同步、网络接口或遥测。
- 多个并行计时任务。
- 今日、本周、本月收入统计或趋势图。
- 自动识别其他应用全屏并取消置顶。
- 自动更新。
- macOS 签名、公证或 Windows 代码签名。
- 将无效记录修复为有效记录。
- JSON 备份与恢复。

- SQLite 的唯一读写入口。

- 暴露类型明确、最小化的 IPC API。

- 每秒基于时间戳刷新运行中显示值。
- 表单即时校验和字段级错误展示。
- 发起状态转换、编辑、查询和导出请求。

安全基线：

- `contextIsolation: true`
- `nodeIntegration: false`
- 限定导航和新窗口行为。
- 所有写操作在主进程重复校验，不能只依赖前端校验。

## 4. 时间与计时模型

### 4.1 权威时间

计时不通过 `setInterval` 累加秒数。数据库保存时间戳，运行中的显示值由“当前系统时间减去片段开始时间”计算。

这保证：

- 窗口隐藏到托盘后不丢失时间。
- 渲染卡顿不会造成累计误差。
- 电脑休眠后恢复时按实际时间继续计算。
- 应用真正退出后仍能识别未完成计时。

数据库中的时间统一保存为 UTC Unix 毫秒时间戳。界面使用当前系统时区显示本地日期和时间，精确到秒。CSV 同时输出本地时间和时区偏移。

如果系统时间倒退到当前开放片段的开始时间之前，界面冻结实时结算并显示时间异常，要求用户调整时间后再继续或结束，不能生成负时长。

### 4.2 时间片段

每局由一个或多个有效计时片段组成：

```text
片段 1：开始 → 暂停
片段 2：继续 → 暂停
片段 3：继续 → 结束
```

字段语义：

- 第一段起点显示为“开始时间”。
- 后续片段起点显示为“继续时间”。
- 非最后结束的片段终点显示为“暂停时间”。
- 完成记录最后片段终点显示为“结束时间”。

有效秒数：

```text
总有效秒数 = Σ(片段结束时间 - 片段开始时间)
有效分钟 = ceil(总有效秒数 / 60)
```

所有片段先累加秒数，再整体向上取整。不对每个片段分别取整。

示例：

```text
片段 1：10分30秒
片段 2：5分10秒
总有效时长：15分40秒
有效分钟：16分钟
```

## 5. 计费规则

### 5.1 默认参数

- 每小时单价：`40元`
- 每小时抽成：`3元`
- 默认计费方式：`15分钟阶梯档`

空闲状态或设置页修改参数时，保存为下一局默认值。计时中的参数修改只影响当前局，不覆盖全局默认值。

每局创建时复制当前默认参数，历史记录永久保存当局参数。完成记录调整时间后，使用该记录保存的参数重算，不使用当前全局设置。

### 5.2 输入限制

- 每小时单价必须为正整数。
- 每小时抽成必须为正整数。
- 计费方式必须是支持的三个枚举值之一。
- 非法输入不能保存，当前有效结果继续显示。

### 5.3 三种计费方式

#### 15分钟阶梯档

先计算完整小时，再对剩余分钟应用阶梯：

- `0-10` 分钟：计费 `0` 分钟
- `11-20` 分钟：计费 `15` 分钟
- `21-40` 分钟：计费 `30` 分钟
- `41-50` 分钟：计费 `45` 分钟
- `51-59` 分钟：计费 `60` 分钟

超过一小时按“完整小时 + 剩余分钟阶梯”继续计算。

#### 15分钟起算档

只计算已经完成的 15 分钟区块：

```text
计费分钟 = floor(有效分钟 / 15) × 15
```

例如 `1-14` 分钟计费为 `0`，`15-29` 分钟计费为 `15`。

#### 1分钟档

```text
计费分钟 = 有效分钟
```

由于有效秒数整体向上取整，开始计时后只要产生正有效秒数，1 分钟档至少计费 1 分钟。

### 5.4 金额公式

```text
应得金额 = 计费分钟 / 60 × 每小时单价
抽成金额 = 计费分钟 / 60 × 每小时抽成
```

显示金额统一保留两位小数。内部计算避免通过重复四舍五入累积误差，只有最终展示和持久化结果按两位小数规范化。

计时期间每秒刷新显示，但金额只在有效分钟向上取整值或计费档位发生变化时产生新结果。

## 6. 会话状态机

会话状态：

- `running`：正在计时，最后一个片段只有开始时间。
- `paused`：已暂停，所有片段均已闭合。
- `completed`：正常结束，可以计算金额并编辑时间。
- `invalid`：异常退出后被放弃的永久无效记录。

状态转换：

```text
idle → running
running → paused
paused → running
running → completed
paused → completed
running/paused → invalid（仅启动恢复流程）
```

任何时刻最多存在一个 `running` 或 `paused` 会话。

### 6.1 开始

- 点击“开始计时”后立即以当前系统时间创建第一段。
- 不在开始前弹出时间确认。
- 使用当前默认计费参数。
- 创建成功后立即持久化并进入 `running`。

### 6.2 暂停

- 以当前时间闭合开放片段并进入 `paused`。
- 暂停期间有效时长和金额保持不变。
- 允许在暂停状态直接结束本局。

### 6.3 继续

- 以当前时间创建新片段并进入 `running`。
- 暂停时间与继续时间可以完全相等，表示暂停 `0` 秒。

### 6.4 结束

- 从 `running` 结束时，以当前时间闭合开放片段。
- 从 `paused` 结束时，不创建额外片段。
- 校验全部片段后计算并保存最终结果，进入 `completed`。
- 结束页提供“调整时间”“查看历史”和“开始新一局”。

### 6.5 无效记录

- `invalid` 记录保存原时间信息、原计费参数、备注、失效时间和失效原因。
- 金额与计费分钟固定为 `0`。
- 不允许编辑、不允许重算、不允许转回有效记录。
- 只允许查看、删除和导出。

## 7. 应用退出与恢复

### 7.1 窗口关闭与托盘

- 点击主窗口关闭按钮时隐藏到系统托盘，不退出应用。
- 托盘菜单提供“显示窗口”和“退出应用”。
- 托盘图标点击行为遵循平台习惯，至少可以恢复主窗口。
- 计时或暂停状态在托盘中继续保持。

### 7.2 真正退出

从托盘选择“退出应用”时：

- 当前 `running` 或 `paused` 会话保持未完成状态。
- 已有时间片段、参数和备注在退出前已持久化。
- 下次启动进入恢复询问，不自动结算。

### 7.3 启动恢复询问

发现 `running` 或 `paused` 会话时，必须在进入主界面前提供：

#### 恢复计时

- `running` 保留原开放片段并继续按当前系统时间计算。
- `paused` 恢复为暂停界面，不自动继续。
- 保留参数、备注和全部片段。

#### 重新计时

- 原会话转为 `invalid`。
- 原状态为 `running` 时，用用户作出选择的时间闭合开放片段，仅用于展示原记录时间范围。
- 原状态为 `paused` 时，保留原闭合片段，并单独保存失效时间。
- 原记录金额和计费分钟清零。
- 随后以当前时间立即创建新会话。

#### 不恢复

- 原会话按上述规则转为 `invalid`。
- 不创建新会话，进入空闲界面。

恢复弹窗中“恢复计时”为唯一主按钮。“重新计时”和“不恢复”必须在按钮旁直接说明旧记录将永久无效。

## 8. 时间编辑与合法性校验

### 8.1 可编辑范围

`running`、`paused` 和 `completed` 会话允许编辑所有已经存在的时间节点：

- 开始时间
- 每次暂停时间
- 每次继续时间
- 最终结束时间

运行中编辑后仍保持 `running`；暂停中编辑后仍保持 `paused`；完成记录编辑后仍保持 `completed`。

`invalid` 记录不可编辑。

### 8.2 校验规则

1. 所有输入必须是有效的本地日期时间，精确到秒。
2. 每个有效计时片段的结束时间必须严格晚于该片段开始时间。
3. 下一片段开始时间必须晚于或等于上一片段结束时间。
4. 暂停与继续可以同秒发生，表示暂停 0 秒。
5. 片段不能重叠。
6. `running` 只允许最后一个片段缺少结束时间。
7. `paused` 和 `completed` 的所有片段必须闭合。
8. `completed` 至少包含一个正时长片段。
9. 所有已经发生的节点不得晚于主进程校验时的当前时间。
10. 不能产生负有效时长或无法表示的日期。
11. 单局最多允许 `1000` 个时间片段。

渲染层即时校验，主进程在事务写入前使用同一组领域规则重复校验。主进程结果具有最终权威。

### 8.3 错误反馈

- 非法字段使用错误边框和文字说明。
- 时间线对应节点同时显示错误状态，不能只依赖颜色。
- 编辑页顶部汇总错误数量。
- 有错误时禁用保存，金额区域显示“等待修正”或保留最后一次有效结果，不展示伪造的新结果。
- 主进程拒绝保存时保留用户输入，并映射字段级错误，不清空表单。
- 关闭有未保存修改的编辑器时确认是否放弃。

保存完成记录的合法修改后，立即使用该记录保存的计费参数重算有效秒数、有效分钟、计费分钟、应得金额和抽成金额。

## 9. 参数与备注

### 9.1 本局参数

计时期间允许修改：

- 每小时单价
- 每小时抽成
- 计费方式

合法修改立即持久化到当前会话并重算，只影响当前局。完成后参数成为历史快照。

完成记录首版不支持修改计费参数，只支持调整时间并使用历史参数重算。

### 9.2 默认参数

空闲主界面和设置页允许编辑下一局默认参数。合法修改自动保存到本地设置。

### 9.3 备注

- 备注为可选自由文本，不拆分老板昵称、游戏、平台或订单号。
- 主计时界面不直接放输入框，通过“添加备注”或“编辑备注”打开弹窗。
- 保存后在主界面显示单行摘要，完整内容在弹窗和记录详情中查看。
- 历史记录可以搜索备注。
- 备注不参与计费和时间校验。
- 首版最大长度为 `500` 个 Unicode 字符，保存前去除首尾空白。

## 10. 窗口与桌面行为

### 10.1 主窗口

- 默认尺寸：`720 × 620`
- 最小尺寸：`680 × 560`
- 默认居中打开。
- 记住用户最后一次正常窗口位置，但必须保证重开后窗口仍位于可见显示器范围内。
- macOS 与 Windows 使用相同信息架构，系统标题栏行为遵循平台能力。

### 10.2 迷你计时窗

- 参考尺寸：约 `280 × 160`
- 展示状态、有效时长、应得金额、抽成、暂停/继续和结束。
- 提供手动“置顶/取消置顶”。
- 记住最后一次置顶状态。
- 首版不检测其他应用全屏状态。
- 切换到迷你窗时隐藏主窗口；通过迷你窗或托盘可恢复主窗口。
- 迷你窗与主窗口共享主进程会话快照，不能维护独立计时状态。

### 10.3 单实例

应用使用单实例锁。再次启动时聚焦已有窗口；若尚在启动恢复流程，则聚焦恢复弹窗，不能创建第二个计时实例。

## 11. 信息架构与视觉方向

视觉方向采用已确认的“A 方向：深色低干扰控制台”。

设计原则：

- 当前一局是主界面的唯一内容中心。
- 不在计时页面放今日局数、今日收入或其他统计卡片。
- 主导航仅包含“计时”“历史”“设置”。
- 深炭黑中性色作为背景，青绿色只表达活动状态、主结果和主要操作。
- 暂停状态可使用克制的琥珀色辅助识别，错误使用明确文字和错误色。
- 使用等宽数字字体显示时长和金额，普通界面文本使用系统字体。
- 动效仅用于状态变化，持续时间约 `150-250ms`，并尊重减少动态效果设置。
- 主要按钮、输入和焦点状态满足键盘操作与 WCAG AA 对比度要求。

### 11.1 计时页

信息顺序：

1. 当前状态与“调整时间”“编辑备注”。
2. 本局有效时长、开始时间、累计暂停和当前片段。
3. 当前应得金额和抽成金额。
4. 备注摘要与本局计费参数。
5. 暂停/继续和结束本局。

### 11.2 空闲、暂停和完成状态

- 空闲：参数摘要与唯一主按钮“开始计时”。
- 暂停：“继续计时”为主操作，“结束本局”为次级操作。
- 完成：显示结算依据，并提供调整时间、查看历史、开始新一局。

### 11.3 历史页

- 使用按日期分组的纵向记录列表，不使用需要宽窗口的桌面表格。
- 每条记录展示时间范围、备注、有效时长、计费分钟、应得金额和抽成。
- 无效记录明确标记，金额显示为 0。
- 支持备注搜索和有效/无效状态筛选。

### 11.4 时间编辑页

- 在同一主窗口内切换为专注编辑页。
- 使用纵向时间线展示计时片段和暂停间隔。
- 字段错误直接出现在对应时间节点下方。
- 顶部汇总错误，底部显示当前重算状态。

## 12. 数据模型

### 12.1 sessions

建议字段：

- `id`
- `status`: `running | paused | completed | invalid`
- `note`
- `billing_mode`: `15-step | 15-floor | minute`
- `hourly_rate`
- `commission_rate`
- `effective_seconds`
- `effective_minutes`
- `billed_minutes`
- `gross_amount`
- `commission_amount`
- `invalid_reason`
- `invalidated_at`
- `created_at`
- `updated_at`
- `completed_at`

金额字段使用固定精度表示，不能使用不受约束的二进制浮点持久化。具体使用整数分或定点十进制在实现计划中固定。

### 12.2 time_segments

建议字段：

- `id`
- `session_id`
- `sequence`
- `started_at`
- `ended_at`，仅 `running` 的最后一段允许为空
- `created_at`
- `updated_at`

`session_id + sequence` 唯一。删除会话时级联删除片段。

### 12.3 app_settings

建议保存：

- 默认计费方式
- 默认每小时单价
- 默认每小时抽成
- 迷你窗置顶状态
- 主窗口最后位置
- 数据库架构版本

数据库存放在 Electron `userData` 目录。通过版本化迁移升级，迁移必须在窗口创建前完成；迁移失败时不覆盖原数据库，并显示可理解的启动错误。

## 13. 历史记录与 CSV 导出

### 13.1 历史操作

- 默认按开始时间倒序、按本地日期分组。
- 支持备注搜索。
- 支持全部、有效、无效状态筛选。
- `completed` 可以查看、调整时间和删除。
- `invalid` 可以查看和删除，不能编辑。
- 删除前显示包含记录时间和备注摘要的确认提示。

### 13.2 CSV 导出

- 支持选择日期范围，默认沿用当前历史筛选范围。
- 通过系统保存对话框选择位置。
- UTF-8 with BOM，确保 Windows Excel 正确显示中文。
- 每局一行，时间片段用清晰、稳定的文本格式合并到单列，避免重复金额。

字段至少包括：

- 记录 ID
- 状态
- 无效原因
- 开始时间
- 结束/失效时间
- 时间片段
- 总有效秒数
- 有效分钟
- 计费分钟
- 计费方式
- 每小时单价
- 每小时抽成
- 应得金额
- 抽成金额
- 备注
- 创建时间
- 最后修改时间

CSV 导出失败时不创建半成品文件，并显示失败原因。

## 14. 持久化与一致性

- 开始、暂停、继续、结束、恢复选择、时间编辑、参数修改和备注修改均使用 SQLite 事务。
- 不每秒写数据库；每秒刷新只发生在渲染层。
- 主进程完成写入后生成统一会话快照，广播给主窗口和迷你窗。
- 金额结果与时间片段在同一事务中更新，避免时间已修改而金额未更新。
- 启动时数据库状态是恢复流程的唯一权威来源，不依赖渲染层缓存。
- 应用不调用网络服务，也不发送使用数据。

## 15. 错误处理

- 数据库初始化或迁移失败：阻止进入正常界面，保留原数据库，提供数据库路径和重试/退出操作。
- 写入失败：保持界面最后确认状态，显示操作未保存，允许重试。
- 非法时间：字段级提示，禁止保存或结束。
- 系统时钟异常：冻结依赖当前时间的实时结算，要求修正。
- CSV 写入失败：显示系统错误，不改变历史记录。
- 主窗口意外销毁：通过托盘重新创建窗口并加载主进程快照。
- 不吞掉主进程异常；日志仅写入本机应用日志目录，不包含无关隐私信息。

## 17. 测试策略

### 17.1 计费单元测试

覆盖：

- 有效秒数整体向上取整边界：`0`、`1`、`59`、`60`、`61` 秒。
- 15分钟阶梯档所有边界及跨小时情况。
- 15分钟起算档的 `14/15/29/30` 分钟边界。
- 1分钟档。
- 应得金额和抽成金额的两位小数。
- 非法单价、抽成和计费方式。

### 17.2 时间校验测试

覆盖：

- 正常单段和多段记录。
- 暂停与继续同秒。
- 零时长有效片段。
- 片段重叠、逆序和未来时间。
- `running` 开放片段约束。
- `paused/completed` 全闭合约束。
- 1000 片段上限。
- 完成记录编辑后的重算。

### 17.3 状态机测试

覆盖全部合法和非法转换，以及：

- 从运行和暂停状态结束。
- 恢复 `running` 与 `paused`。
- 重新计时生成无效旧记录和新会话。
- 不恢复只生成无效记录。
- 同时只允许一个活动会话。

### 17.4 持久化与 IPC 测试

覆盖：

- 事务提交和回滚。
- 数据库迁移。
- 主窗口和迷你窗收到同一快照。
- 渲染层不能调用未暴露的 Node/IPC 能力。
- CSV 中文、引号、换行和时间片段转义。

### 17.5 Electron 端到端测试

至少覆盖：

1. 空闲开始、暂停、继续、结束并生成历史。
2. 计时中修改参数和备注后实时重算。
3. 调整时间出现字段错误，修正后成功保存。
4. 关闭到托盘并恢复窗口。
5. 真正退出后重启，分别选择恢复、重新计时和不恢复。
6. 主窗口与迷你窗切换及手动置顶。
7. CSV 导出。

## 18. 验收标准

- macOS 和 Windows 都能启动、计时、暂停、继续和结束。
- 实时显示使用时间戳计算，不因窗口隐藏或渲染暂停丢秒。
- 有效秒数整体向上取整后正确应用三档计费规则。
- 当前应得金额与抽成金额随计费边界同步变化。
- 所有时间节点均可按状态规则调整，并具有双层校验。
- 暂停与继续同秒合法，任何有效片段零时长非法。
- 异常退出后必须出现三选项恢复流程。
- 重新计时和不恢复均生成永久无效、金额为 0 的旧记录。
- 完成记录调整时间后使用历史参数重算。
- 无效记录不可编辑。
- 主窗口默认 `720 × 620`、最小 `680 × 560`，计时页不显示收入统计。
- 迷你窗可手动置顶并记住状态。
- 点击主窗口关闭按钮进入托盘，托盘可以显示窗口和退出应用。
- 历史记录可搜索、筛选、删除和导出 CSV。
- 应用完全离线，无网络依赖和遥测。
- GitHub Actions 能在对应平台生成未签名安装包。
